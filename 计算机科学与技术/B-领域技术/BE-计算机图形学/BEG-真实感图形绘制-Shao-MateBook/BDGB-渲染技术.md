**渲染算法要回答的核心问题是可见性：从视点看过去，每个像素上是哪个表面、它是什么颜色。按解决可见性的方式，经典算法可以分成四条路线：逐像素比较深度的深度缓冲（Z-Buffer），逐行处理多边形的扫描线算法，只画可见线条的隐藏线消除，以及从视点发射光线求交的光线追踪。前三者属于“从物体到像素”的光栅化思路，光线追踪则是“从像素到物体”。**

> 参考：Foley 等《Computer Graphics: Principles and Practice》可见面判定一章；Sutherland、Sproull、Schumacker, *A Characterization of Ten Hidden-Surface Algorithms*（1974）；Pharr 等《Physically Based Rendering》。

## 四种路线对比

| 特性 | 深度缓冲 | 扫描线 | 隐藏线消除 | 光线追踪 |
| --- | --- | --- | --- | --- |
| 主要用途 | 实时 3D 渲染 | 早期图形系统、早期离线渲染器 | 工程线框图、技术插图 | 高质量离线渲染，近年进入实时 |
| 可见性判定 | 逐像素深度比较 | 每条扫描线上按深度选最近的多边形段 | 线段可见性测试 | 光线与场景求交，取最近交点 |
| 额外内存 | 与分辨率等大的深度缓冲 | 边表、活动边表，与分辨率无关 | 小 | 加速结构（BVH 等），与场景规模相关 |
| 开销主要取决于 | 光栅化的片元总数（分辨率 × 深度复杂度） | 边和扫描线交点的数量 | 线段数 × 遮挡面数 | 光线数 × 每条光线的求交代价（有加速结构时约为场景规模的对数） |
| 图像质量 | 需要额外手段处理走样、阴影、反射 | 同左 | 只有轮廓线 | 阴影、反射、折射天然正确 |
| 可处理的几何 | 任意可光栅化的图元，互相穿插也没问题 | 多边形 | 线框 / 多边形模型 | 任何能求交的几何 |
| 实时性能 | 优秀（GPU 硬件实现） | 软件实现，现已少用 | 中等 | 传统上差，专用硬件出现后可实时 |
| 实现难度 | 简单 | 复杂 | 中等 | 基本算法简单，高效实现非常复杂 |

## 深度缓冲

| 中文名 | 外文名 | 别名 |
| --- | --- | --- |
| 深度缓冲 | Depth Buffer | Z-Buffer（Z 缓冲区） |

深度缓冲为每个像素额外存一个深度值，记录目前为止画到这个像素上的最近表面有多远。每光栅化出一个片元，就把它的深度和缓冲里的值比较，更近才写入颜色并更新深度。它不需要对物体排序，互相穿插的多边形也能正确处理，这是它相对画家算法（按深度从远到近排序后依次画）的根本优势；画家算法效率低，但天然支持半透明物体按顺序混合，深度缓冲在这点上反而需要额外处理。

![[Pasted image 20260104143724.png]]

深度缓冲的思想由 Edwin Catmull 在 1974 年的博士论文中提出，Wolfgang Straßer 同年的博士论文里也独立描述了相同的方法。之后深度缓冲的压缩、快速清除等技术逐步进入图形硬件，今天的 GPU 把它做成了固定功能单元；光线追踪等其他渲染方法也会借助深度缓冲加速（例如混合渲染里先光栅化主可见性）。

```pseudocode
初始化：
    深度缓冲区 ← 最大深度值（通常为 1.0 或远裁剪面距离）
    颜色缓冲区 ← 背景颜色

对于每个多边形：
    对于多边形覆盖的每个像素 (x, y)：
        计算该像素处的深度 z
        如果 z < 深度缓冲区[x][y]：
            深度缓冲区[x][y] ← z
            颜色缓冲区[x][y] ← 多边形在该像素的颜色
```

一套典型的缓冲组合：

| 缓冲 | 内容 | 常见格式 |
| --- | --- | --- |
| 深度缓冲 | 每像素深度 | D16、D24、D32F |
| 模板缓冲 | 每像素 8 位整数，用于遮罩、阴影体、描边等 | 常与 D24 打包成 D24S8 |
| 颜色缓冲 | 最终颜色 | RGBA8、RGBA16F 等 |

**深度精度。** 透视投影后存入缓冲的不是线性距离。以 Direct3D 的 $[0, 1]$ 深度范围为例，近平面 $n$、远平面 $f$ 时，视空间深度 $z$ 映射为

$$
z_{\text{ndc}} = \frac{f}{f - n}\left(1 - \frac{n}{z}\right)
$$

它和 $1/z$ 成线性关系，大部分精度集中在近平面附近，远处两个相距很近的表面会映射到同一个深度值，出现 Z-fighting（深度冲突，两个表面交替闪烁）。16 位缓冲在大场景里几乎必然出问题，24 位或 32 位好得多。把近平面往远处推一点，对远处精度的改善比把远平面拉近有效得多。

**改进。**

| 技术 | 做法 |
| --- | --- |
| W-Buffer | 存线性的视空间深度 $w$ 而不是 $z/w$，精度在整个范围内均匀分布；现代硬件基本不再支持 |
| 反向 Z（Reversed-Z） | 近平面映射到 1、远平面映射到 0，配合浮点深度缓冲，浮点数在 0 附近密集的特性正好抵消 $1/z$ 分布，远处精度大幅改善。UE 默认使用反向 Z |
| 分层 Z（Hierarchical Z） | 维护低分辨率的深度金字塔，整块被遮挡的图元或像素块可以提前剔除 |
| Early-Z | 在像素着色之前做深度测试，被遮挡的片元不再执行着色器；着色器里写深度或 discard 会让它失效 |
| 深度预通道（Z-Prepass） | 先只写深度画一遍，第二遍着色时每个像素只着色一次 |
| 可见性缓冲（Visibility Buffer） | 光栅化时只写深度和三角形 ID，着色推迟到之后；UE 的 Nanite 用 64 位原子操作把深度和 ID 一起写入 |

实现上还有压缩、快速清除、用 SIMD 加速软件光栅化（遮挡剔除常用）等优化。深度缓冲的固有问题是：同一像素上可能被多次着色而只有最后一次有效（过度绘制），以及无法直接处理需要按顺序混合的半透明物体。

## 扫描线算法

扫描线渲染按屏幕上从上到下一行一行地处理像素。它利用“扫描线连贯性”：相邻两行上，多边形边的交点位置、表面深度都只有微小的增量变化，可以增量计算而不必每行重算。早期内存昂贵，存不起整屏深度缓冲，扫描线算法只需维护当前一行的数据，这是它流行的原因（Wylie 等 1967 年、Watkins 1970 年的工作是代表）。

作为“渲染器”这个词使用时，“扫描线渲染”常指 3ds Max 等软件早年的默认渲染引擎：它用扫描线方式求可见性，本身不支持全局照明，无法准确计算光线的多次反射，阴影和间接光的效果受限。数字城市建模等工程领域常用烘焙贴图把预先算好的光照写进纹理来弥补。

核心数据结构有两个：

**边表（ET，Edge Table）** 存所有非水平边，按边的下端（扫描起始行）分桶。每条边记录：

```plaintext
- y_max：边的上端点 y 坐标（扫描到这一行时移除）
- x：边与当前扫描线交点的 x（初始为下端点的 x）
- 1/m：斜率的倒数 dx/dy，每下一行 x 增加这么多
- 所属多边形的指针
```

**活动边表（AEL，Active Edge List）** 存与当前扫描线相交的边，按交点 x 排序。

```pseudocode
按起始扫描线把所有边放入 ET
for 每条扫描线 y（从上到下或从下到上）：
    1. 把 ET 中从这一行开始的边加入 AEL
    2. AEL 按交点 x 排序
    3. 相邻交点两两配对，得到若干区间 [x_left, x_right]
    4. 对每个区间，找出覆盖它的多边形中深度最小的那个
    5. 用该多边形的颜色填充区间
    6. 移除 AEL 中到达 y_max 的边
    7. 所有剩余边 x += 1/m
```

深度可以增量计算。多边形所在平面 $z = Ax + By + C$，同一扫描线上向右一个像素 $z$ 增加 $A$，换到下一行增加 $B$，整行只需一次乘法初始化。

扫描线算法内存省、易于在一行内做抗锯齿，但实现比深度缓冲复杂得多，处理互相穿插的多边形需要额外拆分，场景变化时边表要重建，与 GPU 的硬件流水线也不契合，今天主要出现在教材和软件光栅化器里。

## 隐藏线消除

在线框图里，所有边都画出来会产生二义性：分不清哪条边在前、哪条在后。消隐技术的目标是去掉被遮挡的线或面，消除视觉歧义、增强真实感。按在哪个空间里判定可见性，消隐算法分为两大类：

| 类别 | 做法 | 例子 |
| --- | --- | --- |
| 图像空间 | 在像素精度上判定 | 深度缓冲、扫描线 |
| 物体（景物）空间 | 在几何精度上计算遮挡关系 | 画家算法、Roberts 算法、Appel 的“定量不可见性” |
| 混合 | 两者结合 | 层次遮挡图（Hierarchical Occlusion Map） |

隐藏线消除是最早被研究的可见性问题：Lawrence Roberts 1963 年的博士论文处理了凸多面体的隐藏线，Arthur Appel 1967 年提出了“定量不可见性”（沿边行走，遇到轮廓线就更新被遮挡的层数），这两项工作是后来所有可见性算法的起点。

常见的实现方法：

- **基于表面的方法**：把线框模型当作表面模型，用深度缓冲或扫描线算出每个像素的可见表面，然后只画可见表面边界上的线。
- **优先级方法（画家算法的变种）**：把表面按深度排序，从后往前处理，把被前面的面盖住的线段部分标记为隐藏。
- **浮动水平线算法**：专门用于 $y = f(x, z)$ 这类函数曲面，从前往后逐条画截面曲线，维护上、下两条“水平线”，只有超出这两条线的部分可见。

基于表面的方法的流程：

```pseudocode
1. 用深度缓冲或扫描线求出每个像素的可见表面深度
2. 对每条边：
     a. 在边上采样若干点
     b. 计算每个采样点的深度，与对应像素的深度缓冲比较（留一个小偏移）
     c. 全部可见 → 整条画出；全部被遮挡 → 不画；部分可见 → 裁剪后只画可见段
3. 绘制可见边
```

表现上常见的约定：外轮廓线加粗，隐藏线用虚线或浅色画出而不是直接删掉（工程制图惯例），按深度调整线条亮度或粗细作为深度提示；表面之间的交线需要单独精确计算可见性。隐藏线图保持了线框的简洁，数据量小，适合工程和技术绘图，但它需要表面信息，处理曲面困难，也表达不了材质和光照。今天实时渲染里的描边、卡通渲染轮廓线，本质上是在光栅化结果上重新做这件事。

## 光线追踪

光线追踪通过模拟光线在场景中的传播来生成图像：从相机穿过每个像素发射一条光线，找到它最先碰到的表面，在交点处计算光照，再根据材质继续追踪反射、折射光线。它天然正确地处理阴影、镜面反射、折射，路径追踪等扩展还能计算全局光照。

历史脉络：Arthur Appel 1968 年用光线投射做可见性和阴影；Turner Whitted 1980 年提出递归光线追踪，处理镜面反射和折射；Robert Cook 等 1984 年的分布式光线追踪处理软阴影、景深、运动模糊；James Kajiya 1986 年提出渲染方程和路径追踪，给出了全局光照的统一框架。

长期以来它因计算量巨大，只用于电影、广告等离线渲染。2018 年微软发布 DXR（DirectX Raytracing），NVIDIA 推出带专用光线追踪单元（RT Core）的 Turing 架构 GPU，同时用基于 AI 的降噪和超分辨率（DLSS）弥补每像素光线数的不足，实时光线追踪开始进入游戏。2020 年的 PS5、Xbox Series 主机采用带光追硬件的 AMD RDNA 2 架构，2026 年发售的新款 Steam Machine（RDNA 3 架构 GPU）同样支持硬件光追。今天的应用包括游戏的混合渲染、汽车等工业设计的可视化评审（例如用 UE 的光线追踪、路径追踪检查车漆和镀铬件的反射），以及无线通信中模拟电磁波传播的射线追踪建模。UE 里对应的是 Lumen 的硬件光追模式和离线质量的 Path Tracer。

核心思想有三点：**逆向追踪**，从相机而不是光源出发，因为光源发出的光绝大部分到不了相机；**递归**，在交点处继续追踪反射、折射光线；**蒙特卡洛积分**，用随机采样估计漫反射、软阴影、全局光照这类需要对半球积分的效果。

```pseudocode
function TraceRay(ray, depth):
    if depth > MAX_DEPTH:
        return BACKGROUND_COLOR

    hit = FindClosestIntersection(ray)          // 1. 最近交点
    if no hit:
        return BACKGROUND_COLOR

    color = 0
    for each light:                             // 2. 直接光照 + 阴影测试
        shadowRay = ray from hit.point to light
        if not Occluded(shadowRay):
            color += Shade(hit, light)

    if hit.material is reflective:              // 3. 递归反射
        color += TraceRay(Reflect(ray, hit), depth + 1) * reflectivity

    if hit.material is transparent:             // 4. 递归折射
        color += TraceRay(Refract(ray, hit), depth + 1) * transparency

    return color
```

阴影测试要在累加直接光照之前做，被遮挡的光源不贡献光照；把阴影放在最后对总颜色乘系数，会连反射进来的光一起压暗。

### 关键组成

**光线表示。** $\mathbf{r}(t) = \mathbf{o} + t\,\mathbf{d}$，$t \in [t_{\min}, t_{\max}]$。$t_{\min}$ 取一个小正数，避免次级光线和出发的表面自相交（“阴影痤疮”）。

**求交。**

| 几何 | 方法 |
| --- | --- |
| 球 | 代入球面方程，解一元二次方程 |
| 平面 | 解线性方程 |
| 三角形 | Möller–Trumbore 算法，直接解出重心坐标和 $t$ |
| 轴对齐包围盒 | Slab 方法，求三对平行平面的进出区间交集 |

**材质模型。** 漫反射用 Lambert 模型；镜面高光的经验模型有 Phong、Blinn-Phong；折射方向由 Snell 定律决定，反射与折射的能量比例由 Fresnel 方程给出；现代渲染器普遍用基于微表面理论的 BRDF，也能表达各向异性材质。

**光照。** 直接光照来自点光源、方向光、面光源；间接光照靠路径追踪或光子映射；环境光部分常用环境光遮蔽和基于图像的光照（IBL）近似。

### 加速结构

不加速时每条光线要和所有图元求交，开销与场景规模成正比。加速结构把它降到大约对数级别：

| 技术 | 原理 | 特点 |
| --- | --- | --- |
| BVH（包围体层次） | 按物体分组，递归构建层次包围盒 | 构建和更新快，适合动态场景；DXR / Vulkan RT 的硬件加速结构就是 BVH |
| KD-Tree | 递归用轴对齐平面二分空间 | 静态场景下遍历效率高，构建慢、更新难 |
| BSP 树 | 用任意平面递归划分空间 | 早期引擎用于可见性和碰撞 |
| 均匀网格 | 把空间切成等大格子 | 简单，物体分布均匀时有效，分布不均时浪费严重 |
| 光束 / 光线包追踪 | 同时追踪一束相邻光线 | 共享遍历，利用 SIMD 和相干性 |

### 在基本算法之上

| 技术 | 说明 |
| --- | --- |
| 路径追踪 | 每次反弹随机采样一个方向，对渲染方程做无偏蒙特卡洛估计，是离线渲染的主流 |
| 双向路径追踪 | 同时从相机和光源出发构造路径再连接，擅长处理光源难以直接到达的场景 |
| 光子映射 | 两遍法：先从光源发射光子并存储，再从相机追踪、查询附近光子估计间接光，焦散效果好，结果有偏但一致 |
| 辐射度 | 源自热传递中的辐射换热理论，在漫反射表面之间求解能量平衡，与视点无关，早年用于建筑可视化和光照烘焙 |
| 实时光线追踪 | 专用硬件加速求交，每像素只追踪很少的光线，依赖时空降噪和超分辨率 |

光线追踪的图像质量最高，理论上能模拟几何光学范围内的所有现象，代价是计算量大、加速结构占内存、实现和调试复杂，以及蒙特卡洛采样带来的噪声，需要足够多的样本或降噪才能收敛到干净的图像。
