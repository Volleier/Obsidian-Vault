写法约定（注释在阅读视图里不显示，写完可以整段删掉）

整体
- 一篇只讲一个知识点，写成查阅用的百科条目，不写成"第一步、第二步"的学习日记。
- 下面的 ## 标题全部按内容起名，比如"为什么要有 X""X 和 Y 的关系""存储方式""容易踩的坑"。每篇都可以不一样。
- 禁用标题：基本概念 / 介绍 / 概述 / 工作流程 / 应用场景 / 优缺点 / 优点 / 挑战 / 结论 / 总结。
- 不写结尾总结段。最后一节写完就停。
- 禁用套话：旨在、特别适用于、被广泛应用、显著提升、总的来说、通过合理使用……可以……、值得注意的是。

正文
- 以连贯的段落为主，讲清楚"为什么这样设计"，而不只是"有什么"。先说问题，再说它的做法，最后说代价。
- 列表只放真正并列的短项，不要把一段话拆成几条完整句子。
- 能对照的内容做成表格：术语对照、类型区别、参数和选项、版本差异、模块位置。
- 每个说法都要能追到出处。不确定的写清楚"没核实""以 x.x 为准"，不要编。
- 同一个概念只在一个地方讲透，别处用一句话加链接带过。

代码
- 只贴真实 API：完整的声明（USTRUCT / UCLASS / 头文件）加实现，注释用中文、写短。
- 不写与主题无关的通用演示代码。代码前后各用一两句话说明它在干什么、要注意什么，不要把代码逐行复述一遍。
- 版本敏感的写法在代码旁边标出来。
