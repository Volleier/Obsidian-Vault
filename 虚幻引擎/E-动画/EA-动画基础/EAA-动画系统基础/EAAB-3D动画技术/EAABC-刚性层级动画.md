**刚性层级动画（Rigid Hierarchical Animation）是把角色或物体拆成若干个不变形的刚性部件，按父子关系组织成一棵层级树，每个部件只随自己所挂的关节做旋转和平移的动画方式。《Game Engine Architecture》把它列为游戏角色动画最早的几种技术之一；它的主要缺点是关节处会"开裂"（cracking），后来被蒙皮动画取代，但在机械、载具、道具上至今仍然是最合适的做法。UE 里它对应两种形式：组件层级 / 插槽挂接（`USceneComponent::AttachToComponent`），以及每个顶点只绑定一根骨骼、权重为 1 的骨骼网格体。**

> 参考：《Game Engine Architecture》第 3 版动画系统一章（Rigid Hierarchical Animation、Skeletons、Poses 各节）。

## 结构

GEA 举的例子是一个人形角色，拆成骨盆、躯干、上臂、前臂、大腿、小腿、手、脚、头这些刚性块。骨盆是根，躯干和两条大腿是它的直接子节点，上臂挂在躯干下，前臂挂在上臂下，依此类推。每个刚性块是一个独立的网格，顶点坐标定义在自己所属关节的局部空间里。

动画数据只记录每个关节相对于父关节的局部变换（通常是缩放、旋转四元数、平移的 SRT 形式）。渲染时，从根往下把局部变换逐级相乘，得到每个关节在模型空间中的全局变换，再用它去变换挂在这个关节上的整块网格。

## 变换的级联

用 GEA 的行向量约定（点写在左边，$\mathbf{v}' = \mathbf{v}\mathbf{M}$），设关节 $j$ 的父关节是 $p(j)$，$\mathbf{P}_{j\to p(j)}$ 是它相对父关节的局部姿势，那么它的全局姿势（从关节空间到模型空间）是

$$
\mathbf{P}_{j\to M} = \mathbf{P}_{j\to p(j)}\,\mathbf{P}_{p(j)\to M}
$$

展开就是从自己一路乘到根：

$$
\mathbf{P}_{j\to M} = \mathbf{P}_{j\to p(j)}\,\mathbf{P}_{p(j)\to p(p(j))}\cdots\mathbf{P}_{0\to M}
$$

刚性部件上的顶点 $\mathbf{v}_j$（定义在关节 $j$ 的局部空间）在模型空间中的位置就是 $\mathbf{v}_j\,\mathbf{P}_{j\to M}$。每个顶点只受一个关节影响，这就是"刚性"的数学含义。

父关节一动，所有子孙的全局变换都跟着变，这正是层级结构的好处：动画师转一下肩膀，整条手臂自然跟着转，不需要单独给前臂、手 K 帧。

这个级联在实现上有一个常见的技巧：把关节按"父节点一定排在子节点前面"的顺序存成数组，只存父索引，一次顺序遍历就能算完所有全局变换，不需要递归。下面是这个思路的示意代码，用了 UE 的 `FTransform`（UE 的 `FTransform` 乘法 `A * B` 表示先应用 A 再应用 B，和上面的行向量约定一致）：

```cpp
// 由局部姿势计算全局姿势（算法示意）：要求 ParentIndices[i] < i，根节点父索引为 INDEX_NONE
void ComputeGlobalPoses(const TArray<FTransform>& LocalPoses, const TArray<int32>& ParentIndices,
                        TArray<FTransform>& OutGlobalPoses)
{
	OutGlobalPoses.SetNum(LocalPoses.Num());
	for (int32 i = 0; i < LocalPoses.Num(); ++i)
	{
		const int32 Parent = ParentIndices[i];
		// 子的全局 = 子的局部 × 父的全局
		OutGlobalPoses[i] = (Parent == INDEX_NONE) ? LocalPoses[i] : LocalPoses[i] * OutGlobalPoses[Parent];
	}
}
```

UE 的参考骨架 `FReferenceSkeleton` 就保证了父骨骼索引小于子骨骼索引，引擎计算组件空间骨骼变换时也是这样顺序遍历的。乘法顺序写反（`Global[Parent] * Local[i]`）是最常见的错误，在只有平移时看不出来，一旦父节点有旋转就会错。

## 为什么会开裂

刚性部件在关节处是硬接的。上臂和前臂在手肘处各有一个端面，手臂伸直时两个端面对齐；手肘一弯，前臂绕关节旋转，端面的一侧张开出现缝隙，另一侧互相穿插。GEA 用"cracking at the joints"形容这个问题，这是刚性层级动画用在有机角色上时效果不理想的根本原因。

早期游戏的应对办法是：把关节处的部件做成球形或圆柱形，让旋转时端面始终被遮住；或者在关节处多放一个小的连接部件。这些都只是遮掩，没有从根本上解决。真正的解决方案是蒙皮：把刚性部件藏起来，只作为"骨骼"，用一张连续的网格包住它们，关节附近的顶点同时受两根骨骼影响、按权重混合（见 [[EAABH-3D蒙皮动画]]）。从这个角度看，刚性层级动画就是"每个顶点只有一根骨骼、权重为 1"的蒙皮动画特例。

## 仍然适用的场合

机械结构本来就是刚性的：炮塔、机械臂、载具的轮子和悬挂、门、抽屉、直升机旋翼。这些东西用刚性层级动画不但没有开裂问题（机械关节本来就有缝），还比蒙皮便宜：不需要逐顶点混合矩阵，每个部件一个变换就够了，甚至可以直接当静态网格体来渲染。

角色身上的刚性附件也是这个模型：手里的武器、背上的背包、头上的帽子，都是整块跟随某根骨骼运动。GEA 把这类挂接点称为 attach point，是一种在动画混合流程中可以被忽略的特殊关节。

## 在 UE 里

UE 里实现刚性层级动画有几种常见方式：

| 方式 | 做法 | 适用场景 |
| --- | --- | --- |
| 组件层级 | 多个 `UStaticMeshComponent` 按父子关系挂接，用代码、蓝图或 Sequencer 驱动各组件的相对变换 | 门、炮塔、简单机械 |
| 插槽挂接 | 在骨骼网格体上定义 Socket，用 `AttachToComponent` 把道具挂上去 | 武器、背包、帽子等角色附件 |
| 刚性蒙皮的骨骼网格体 | 在 DCC 里每个部件的所有顶点都 100% 绑定到一根骨骼，作为普通 `USkeletalMesh` 导入 | 需要用动画序列、动画蓝图、物理资产的机械角色（机甲、载具） |

插槽挂接的真实写法：

```cpp
// 把武器组件挂到角色手部插槽上
Weapon->AttachToComponent(GetMesh(), FAttachmentTransformRules::SnapToTargetNotIncludingScale, TEXT("hand_r_socket"));
```

插槽名写错时不会报错，武器会挂在骨骼网格体的原点。`SnapToTargetNotIncludingScale` 表示位置和旋转对齐插槽、保留自身缩放，是挂武器时最常用的规则。

第三种方式看似多此一举（明明可以不用蒙皮），实际上很常用：载具的 Vehicle 系统和很多机械角色都用骨骼网格体，因为这样就能直接使用 UE 的动画序列、动画蓝图、物理资产和 IK 节点，工具链统一。GPU 蒙皮在每个顶点只有一根骨骼时开销也不高。

## 容易踩的坑

**用刚性层级做有机角色。** 人物、动物的关节处一定会开裂或穿插，除非是刻意追求的风格（比如木偶、低多边形复古风格），否则应该用蒙皮。

**缩放沿层级传播。** 父节点的非均匀缩放会让子节点在旋转时产生剪切变形，看上去像是部件被压扁了。机械部件尽量只在叶子节点上用缩放。

**矩阵乘法顺序。** 行向量和列向量约定下乘法顺序相反，UE 的 `FTransform` 和 `FMatrix` 都用"先左后右"的行向量约定，照搬用列向量约定的教材公式时要注意翻转。
