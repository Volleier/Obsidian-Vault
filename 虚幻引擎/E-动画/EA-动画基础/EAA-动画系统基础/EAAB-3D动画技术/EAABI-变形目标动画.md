**变形目标动画（Morph Target Animation，在 Maya 里叫 Blend Shape，3ds Max 里叫 Morpher）是为同一个网格预先制作若干个"变形后的版本"（目标形状），运行时按权重把基础网格向这些目标线性混合的动画方式。它是逐顶点动画的一种受限形式：只存少数几个关键形状，而不是每一帧的全部顶点。最典型的用途是面部表情和骨骼蒙皮难以表现的修正形变。UE 里变形目标属于 `USkeletalMesh`，权重可以由动画序列里的同名曲线驱动，也可以用 `SetMorphTarget` 直接设置。**

> 参考：《Game Engine Architecture》第 3 版动画系统一章（Per-Vertex Animation and Morph Targets）；UE 部分对照 5.x 的 FBX Morph Target Pipeline 文档和 Set Morph Target 蓝图 API。

## 为什么需要变形目标

GEA 把变形目标看作逐顶点动画的一种折中：逐顶点动画要为每帧存全部顶点，数据量太大；变形目标只让美术做一组固定的极端姿势（比如"张嘴""微笑""皱眉"），动画在运行时由这些姿势的混合产生。

它尤其适合人脸。GEA 提到人脸由大约 50 块肌肉驱动，表情的微妙之处在于皮肤的褶皱、鼓起和滑动，这些用少量骨骼很难做对。美术可以直接雕刻出每个表情的最终形状，所见即所得。书中也提到另一种趋势：随着算力增长，一些工作室改用带几百个关节的面部骨骼来替代变形目标；还有的两者结合，用骨骼做面部的主要姿势，再用变形目标做细节修正。顽皮狗在《最后生还者》里 Ellie 的面部动画就用了变形目标。

变形目标的另一个重要用途是**修正形变**（corrective shapes）：线性混合蒙皮在肘、膝、肩大角度弯曲时会出现体积塌陷（见 [[EAABH-3D蒙皮动画]]），美术为这些姿势雕刻一个修正形状，当关节弯到一定角度时自动把它混合进来。

## 数学

设基础网格的顶点为 $\mathbf{v}_0$，第 $k$ 个目标形状中对应的顶点为 $\mathbf{t}_k$，权重为 $w_k$。常用的是相对（增量）形式：

$$
\mathbf{v} = \mathbf{v}_0 + \sum_{k=1}^{K} w_k\left(\mathbf{t}_k - \mathbf{v}_0\right) = \mathbf{v}_0 + \sum_{k=1}^{K} w_k\,\boldsymbol{\delta}_k
$$

每个目标只需要存增量 $\boldsymbol{\delta}_k$。相对形式的好处是各个目标可以自由叠加：左眼闭和右眼闭同时为 1 时，两边眼睛都闭上，互不干扰。如果用绝对形式（$\mathbf{v} = \sum w_k \mathbf{t}_k$，要求 $\sum w_k = 1$），就无法表达"同时做两件事"。

权重通常在 $[0, 1]$ 内，但允许超出：大于 1 时形变被夸张，小于 0 时反向。这在调整风格时有用，但超出太多就会出现网格穿插。

增量通常是**稀疏**的：一个"皱眉"目标只影响额头附近几百个顶点，其余顶点的 $\boldsymbol{\delta}_k = \mathbf{0}$。所以存储时只保留非零增量和对应的顶点索引，数据量和"受影响的顶点数"成正比，而不是整个网格。法线也要一起混合，否则光照会保持基础形状的样子，变形后的表面看起来是平的。

变形目标和骨骼蒙皮同时使用时，顺序是：先在绑定姿势的模型空间里对顶点应用变形目标，再对结果做蒙皮。因为目标形状是在绑定姿势下雕刻的，先蒙皮再加增量，增量的方向就不对了。

## 面部动画的常见组织方式

直接给动画师几百个变形目标并不好用，通常会按某种标准组织。FACS（面部动作编码系统）把面部动作分解成一组"动作单元"，很多面部绑定按它来拆分变形目标。苹果 ARKit 的面部追踪输出 52 个 blend shape 系数，这套命名因为手机动捕的普及，成了很多项目的实际标准，UE 的 Live Link Face 应用输出的就是这些曲线。

## 在 UE 里

变形目标通过 FBX 导入：在 DCC 里建好 Blend Shape / Morpher，导出时勾选 Animations 和变形相关选项，UE 导入时勾选 **Import Morph Targets**。按官方文档，Maya 里的变形目标名是 `[BlendShapeNode]_[BlendShape]` 的形式，3ds Max 里是 Morpher 通道名。导入后在骨骼网格体编辑器的 Morph Target Previewer 面板里可以拖动滑块预览。

驱动权重有两条路：

**动画曲线。** FBX 里的 blend shape 动画导入后成为动画序列里的曲线，曲线名和变形目标名相同就会自动驱动它。官方文档的说法是：一段对白动画可能用到任意数量的变形目标，导入后看起来只是一个动画序列，每个变形目标的数据都能在曲线里访问。在动画蓝图里还可以用 Modify Curve 节点修改曲线值，或用 Pose Driver 节点根据骨骼朝向驱动修正形状。

**代码或蓝图直接设置。** `USkeletalMeshComponent`（准确地说是 `USkinnedMeshComponent`）和 `UAnimInstance` 都有 `SetMorphTarget`：

```cpp
// 直接设置变形目标权重（真实 API）
void AMyCharacter::SetBlink(float Alpha)
{
	// 名字必须和骨骼网格体中的变形目标名完全一致
	GetMesh()->SetMorphTarget(TEXT("Blink_L"), Alpha);
	GetMesh()->SetMorphTarget(TEXT("Blink_R"), Alpha);
}

void AMyCharacter::ResetFace()
{
	GetMesh()->ClearMorphTargets(); // 所有权重归零
}
```

组件上的 `SetMorphTarget` 还有第三个参数 `bRemoveZeroWeight`，默认为 true，权重为 0 时把它从活动列表里移除以节省开销。名字写错不会报错，只是没有效果。

动画在驱动同名曲线时，手动设置的值和曲线值可能互相覆盖，具体哪个生效取决于版本和设置（未逐版本核实）；实践中最好让一个变形目标只有一个数据来源。运行时读取动画驱动的当前值要用动画实例的 Get Curve Value，而不是 `GetMorphTarget`，后者只返回手动设置的值，动画播放时常常读到 0，论坛上有不少人为此困惑。

MetaHuman 的面部绑定同时用了面部骨骼、变形目标和驱动修正形状的逻辑，是 GEA 所说的"骨骼 + 变形目标"混合方案的一个现成例子。

## 容易踩的坑

**先蒙皮再加形变。** 顺序颠倒会让增量方向错误，表情在头部转动时"漂移"。引擎内部已经按正确顺序处理，自己写蒙皮或导出管线时要注意。

**目标形状之间冲突。** 两个目标同时作用在同一片顶点上，线性叠加可能过度（比如"张嘴"加"惊讶"让下巴脱臼）。常见的解法是加组合修正形状（combination shape），在两个目标同时激活时抵消多余的形变。

**法线没有更新。** 只混合了位置，光照会暴露形变的不自然。导入时确认法线/切线也作为变形目标数据导入。

**变形目标太多拖慢性能。** 每个活动的变形目标都要处理它影响的顶点，几百个同时激活的变形目标乘以多个 LOD 会有明显开销。低 LOD 可以去掉细节变形目标。
