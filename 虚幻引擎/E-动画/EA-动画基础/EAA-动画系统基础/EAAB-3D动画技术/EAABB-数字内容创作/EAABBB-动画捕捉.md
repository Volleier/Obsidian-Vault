**动画捕捉（Motion Capture，MoCap）是用传感器记录真人（或动物、道具）的运动，再把记录下来的数据解算到数字骨架上、生成动画片段的技术。捕捉到面部表情和手指时常叫表演捕捉（Performance Capture）。它是游戏角色动画最主要的数据来源之一，UE 里对应的是 Live Link 实时流、Take Recorder 录制、IK Rig / IK Retargeter 重定向，以及 5.6 起的 Mocap Manager。**

> 参考：各设备厂商（Vicon、OptiTrack、Xsens、Rokoko 等）公开资料；UE 部分对照 5.x 的 Live Link、Take Recorder 文档与 Mocap Manager 官方教程。

## 为什么用动作捕捉

手 K 动画可以做出任何风格，但写实的人体运动有大量细节：重心在两脚之间的转移、落地时膝盖的缓冲、转身时肩和髋的错位。这些东西手 K 很难做对，做对了也很慢。动捕一次录下来就全部是真的，一个下午能录几十上百个动作，后续主要是清理和修改。影视里最常被提起的例子是《指环王》系列的咕噜，由安迪·瑟金斯表演、动捕驱动数字角色。

动捕的局限同样来自"它是真的"：演员做不到的动作录不出来（超人跳跃、非人类生物）；风格化的卡通动画需要夸张和预备动作，写实的动捕数据反而要大改；数据里的噪声、遮挡丢失和脚底滑动都要人工清理。所以实际生产中动捕和手 K 是配合使用的：动捕打底，动画师在上面调整节奏、加强关键姿势、补上手指和面部。

## 捕捉设备

| 类型 | 原理 | 优点 | 局限 |
| --- | --- | --- | --- |
| 光学被动式 | 多台红外相机拍摄贴在紧身衣上的反光标记点，三角测量出每个点的 3D 位置 | 精度高，可以多人同时捕捉，影视和 3A 游戏的主流 | 需要专门场地，标记点被遮挡时会丢失或错位，后期清理工作量大 |
| 光学主动式 | 标记点自己发光并编码身份 | 标记点不会混淆 | 设备更贵、需要供电 |
| 惯性式 | 每个肢段绑一个 IMU（陀螺仪 + 加速度计 + 磁力计），积分出朝向 | 无需相机、便携，室外也能用 | 位置靠推算，会随时间漂移；脚底接触和全局位移不如光学准确；磁力计怕金属干扰 |
| 无标记视觉 | 普通摄像机加机器学习估计人体姿态 | 成本最低 | 精度和稳定性仍不如专业设备，快速动作和遮挡下容易出错 |
| 面部捕捉 | 头戴式摄像机拍脸，或手机深度摄像头 | 可以和身体捕捉同时进行 | 需要把图像特征解算成面部骨骼或变形目标权重 |

磁力式动捕（用电磁场测量传感器位置）是更早的技术，对周围的金属很敏感，现在已经很少见。

## 从标记点到动画片段

光学动捕的数据处理大致分为以下几步。

**标记识别（labeling）。** 相机只知道空间中有一堆亮点，并不知道哪个点是左肘。软件要为每个点分配身份，并在整段录制中保持连续。两个标记点交叉时身份可能对调（swap），需要人工修正。

**补洞和滤波。** 被遮挡的帧会出现缺口，用插值或刚体约束（同一肢段上的几个点相对位置不变）补上；高频抖动用低通滤波平滑，但滤波太强会把落地冲击这类有意义的高频信息也抹掉。

**解算（solving）。** 把标记点的位置拟合到一副和演员体型匹配的骨架上，得到每个关节每帧的旋转。这一步本质上是一个大规模 IK 问题：找一组关节角，使骨架上的虚拟标记点和实际标记点的距离之和最小。

**重定向（retargeting）。** 演员的身高、臂长和游戏角色不同，直接套用会出现脚踩不到地、手碰不到身体的问题。重定向在保持动作特征的同时，按目标骨架的比例重新计算，常用 IK 保证脚底接触和手部位置。

**清理和编辑。** 修正脚底滑动（foot sliding），调整根运动，把长录制切成独立的循环和过渡片段，再交给动画师润色。

## 在 UE 里

UE 的动捕链路由几块互相独立的功能组成：

| 功能 | 作用 |
| --- | --- |
| Live Link | 实时接收外部数据流的插件框架。数据源（Source）提供若干主体（Subject），每个主体有角色（Role），如 Animation、Transform、Camera。各家设备通过自己的 Live Link 插件或 Live Link Hub 接入 |
| Live Link Pose 节点 | 在动画蓝图里读取某个 Live Link 主体的骨骼数据，可以配重定向资产，把流数据映射到自己的骨架 |
| Live Link Face | iPhone 应用，用 ARKit 的面部追踪把表情曲线实时推给 UE，也可以配合 MetaHuman Animator 做高质量的离线解算 |
| Take Recorder | 把实时数据录成 Sequencer 里的片段或动画序列资产 |
| IK Rig / IK Retargeter | 为源骨架和目标骨架各定义骨骼链和 IK 目标，再在两者之间重定向，可以批量导出重定向后的动画 |
| Mocap Manager | 5.6 加入的工具，把 Live Link 数据源、演员、角色和 Take Recorder 的录制流程整合在一个面板里 |

一个常见的实时预览流程是：启用 Live Link 和设备厂商的插件（Vicon、OptiTrack、Xsens、Rokoko 等都提供 UE 插件），在 Live Link 面板里添加数据源；在角色的动画蓝图里放一个 Live Link Pose 节点，填入主体名称；如果源骨架和角色骨架不同，就配重定向资产或者先驱动一个和源骨架一致的中间角色，再用 IK Retargeter 实时重定向到目标角色。录制时用 Take Recorder，录完的动画可以直接在 Sequencer 里编辑，或导出成动画序列供游戏使用。

离线处理的数据（厂商软件解算好的 FBX）则走普通的动画导入流程，导入到与之匹配的骨架上，再用 IK Retargeter 批量重定向到项目角色。

## 容易踩的坑

**骨架比例差太多。** 演员和角色体型差异大（比如人类演员驱动矮人角色），重定向后手会穿进身体、步幅不对。尽量选体型接近的演员，或者在 IK Retargeter 里针对具体骨骼链调整。

**根运动处理不一致。** 动捕数据的根通常是骨盆在世界中的位移，游戏里需要单独的根骨骼来承载根运动（Root Motion）。导入前要确认根骨骼的位置和朝向约定，否则角色会原地跑或者跑出胶囊体。

**过度依赖滤波。** 把抖动全部滤掉的数据看上去平滑但失去力量感，尤其是落地和击打的瞬间。滤波要分段、分关节处理。

**实时流的时间对齐。** Live Link 数据有网络和处理延迟，多个设备（身体、面部、手指）同时使用时要做时间码同步，否则口型和身体会错位。
